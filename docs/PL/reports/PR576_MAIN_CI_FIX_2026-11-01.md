# Naprawa czerwonego main po PR #575

## Przyczyna i zakres

Main `630bfe8b` miał dwie awarie: [CI](https://github.com/mpieniak01/Venom/actions/runs/41307842087) i [Simulated regression](https://github.com/mpieniak01/Venom/actions/runs/41307842090). Oba workflow wskazały te same dwa testy; Sonar został pominięty z powodu nieudanego backendu, nie z powodu nowego zgłoszenia skanera. Frontend i E2E na main przeszły.

- Test admission przekazywał `None` do endpointu, który po PR #575 rozróżnia zadania na podstawie prawidłowego schematu żądania. Teraz wywołuje konkretny endpoint z `CodingBenchmarkStartRequest` i sprawdza `runtime_busy` dla zwykłego oraz mieszanego zestawu zadań. Dzierżawa jest zwalniana w `finally`.
- Test listy modeli miał niepełną atrapę runtime i utożsamiał konfigurację z załadowaniem. Teraz korzysta z `LLMRuntimeInfo`, jawnej atrapy metadata i czterech obserwacji: model wybrany załadowany, brak załadowanych, brak obserwacji oraz załadowany inny model. Nadal wymaga jednoznacznego dopasowania basename do wybranej instalacji; załadowanie i aktywność są oceniane niezależnie.

Obie pierwotne awarie odtworzono lokalnie przed zmianą: 2 FAIL. Po zmianie wszystkie 6 wariantów PASS. Nie zmieniono kodu produkcyjnego ani strategii różnych bramek PR/main. Przyrost OpenRouter/ZDR z PR #576 pozostaje zachowany.

## Izolacja pełnej walidacji lokalnej

Pierwsze dodatkowe odtworzenie pełnego backendu ujawniło brak bootstrapu przykładowego env oraz rzeczywisty zapis embeddingów w teście podsumowania sesji. Timeout wyłączył worker; przebieg przerwano i nie uznano za zaliczony (9196 PASS, 141 SKIP, dwie awarie). Ograniczona próba diagnostyczna potwierdziła próbę pobrania modelu embeddingów, zablokowaną w prywatnej sieci.

- Utworzono wyłącznie ignorowany `.env.dev` tego worktree z `.env.dev.example`, jak w CI; konfiguracja działającego stosu bez zmian.
- Trzy testy podsumowania otrzymują magazyn przez istniejący parametr `vector_store`; sprawdzają zapis dokładnego podsumowania do atrapy. Usunięto pustą asercję, która zawsze przechodziła.
- Test podsumowania dopuszczono do ścieżki `new-code` w katalogu i zsynchronizowano grupy. Zakresy workflow PR i main pozostają różne.
- Pełny backend uruchomiono jako ubuntu z czterema workerami w prywatnych przestrzeniach sieci i montowań; dostępne było tylko loopback, sockety usług hosta ukryto. Nie uruchamiano drugiego stosu, generacji zadań modeli, Test Zero ani VAST.
